# ATE-40: automatic Dock registration on macOS 27

**Raw WMBridge creation works without a display refresh on this configuration.**
The new highest numbered Desktop shortcut also works. The CLI now observes
native registration before considering the existing virtual-display workaround.
Creation and cleanup used no virtual display in any trial below.

## Environment and scope

Verified locally on macOS **27.0, build 26A428**, arm64, fully enabled SIP,
existing Accessibility trust, unlocked disposable console session. No Atelier
application was running. Work remained in the isolated `atelier-next-ate-40`
jj workspace and prototype; production code is unchanged.

The fresh baseline was one nonmirrored GLKVM screen: CG display 2,
2560×1440 at 60 Hz, mode 20, native display identifier
`20B77EC1-97B7-45BD-8A54-C91C9A356516`. Desktop order was `[3,4,5]`, current 3;
Dock PID 1672 reported three Desktops. This differs from the earlier mirrored
Jump Desktop configuration. The observations establish this build/setup, not
an isolated estimate of OS upgrade effects or universal macOS 27 support.

The bridge's options-0 creation and result signatures still match. No alternate
creation flags, injection, Dock restart, security changes, or private service
requests were needed. Build 26A428 also matches the environment named by
[Native Space Kit](https://github.com/Fjx-dylanZ/native-space-kit/blob/01b7e49718d500ed08add3e95533e2b9b41b2561/docs/findings.md).
Our tests below supply independent local Dock, navigation, and typing evidence.

Private journals, recordings, logs, and static snapshots are under
`.build/ate-40-manual/os-26A428-wArpQz/`. Old OS evidence was not overwritten.

## Raw creation, before any refresh or overview

`raw/creation/` created Desktop **25**, UUID
`09D81CBD-5385-4D35-B413-31A623A2159F`, appended after `[3,4,5]`.
WMBridge dispatch took 4.33 ms; its exact inactive type-0 addition was confirmed
at 4.86 ms. The subsequent read-only diagnosis and Dock inspection independently
reported four Desktops, with current 3 and Mission Control closed. The saved
configuration also contained 25, but saved preferences were not used as proof.

Before opening Mission Control, the actual Atelier engine's numbered switch to
Desktop **4** reached ID 25 in 346 ms. That is the newly required highest number,
which previously failed after raw creation plus display repair on macOS 26.
The saved fixture accepted typing, was visible on Space 25, and closed its
window (210). Its result took 208 ms. Numbered return to Desktop 1 restored ID 3.
The engine temporarily enabled and restored the existing live shortcut, using
its private recovery journal; it wrote no user shortcut preference.

The later overview recording shows four Desktop thumbnails. Its automatic AX
selection did **not** succeed: Dock exposed an `mc` group with no AXChildren,
and no `mc.spaces.list`. Thus the initial diagnostic's zero thumbnail count and
`selectionAXError=-25201` did not describe the visible UI. There was no target
selection, the fixture correctly refused because 25 was inactive, and current
3 remained unchanged. This is a limitation of the old AX diagnostic, not a
native keyboard entry failure. It is not a thumbnail-selection pass.

Raw cleanup removed only 25 and restored the exact original topology. Dock's
count returned to three automatically.

## Why this result differs

`raw-registration.log` captures the actual propagation at creation time:

1. At 12:54:56.868 local time, WindowManager recorded the new type-0 Space and
   ordered IDs `[3,4,5,25]`.
2. At 12:54:56.869, its AdminXPC listener/connection reported `spacesDidChange`.
3. In that same millisecond, Dock logged a WindowManager Space-change delta
   containing `added(25, afterSpaceID: Optional(5))`.

This is direct runtime evidence that Dock receives the addition without our
display workaround. It is stronger evidence than successful allocation alone.
The bridge and log timestamps do not measure exact end-to-end notification latency.

Fresh arm64e binary UUIDs are Dock
`3BDF6A3B-866B-3C07-920C-E9E7FB57B56B`, SkyLight
`8A3B348E-4637-3685-92D0-6CBC2F36A234`, and WindowManagement
`CAD7E669-DFF8-3CA2-BCA4-8EB1BFC0BEBA`.
Dock's numbered shortcut helper at `0x100007A40` still reads `allUserSpaces`
and calls `CGSSetSymbolicHotKeyWithOptions`/`CGSRemoveHotKey`. The fresh direct
branch inventory reaches its thunk at `0x1000A5C60` from four sites, including
`0x10018947C`, following a wallpaper `addSpace:forDisplayUUID:` call. The other
sites are `0x10018A1A0`, `0x10018B984`, and `0x10018BDEC`.
These static observations are supporting context; the actual shortcut test is
the evidence of registration. No address from the old build was invoked or reused.

## CLI change and measurements

After exact creation and adjacent placement, the CLI samples Dock's independent
count while checking the full native census, including UUIDs, order, display,
and current Space. Counts must agree for 50 ms within a 150 ms polling window.
Success skips the virtual display and its one-second setup observation interval.
A stable topology with lagging counts uses the existing repair. Query failure
or changed topology stops the flow instead of authorizing a display mutation.
Cleanup applies the same observation after guarded removal.

This is a behavior check, not an OS-version switch. Reports preserve the count
samples and `registrationMethod` (`native` or `virtual-display`). The older
repair path remains available; its added polling overhead is at most roughly
150 ms plus query/scheduling time. That path was not rerun on macOS 26 after
the upgrade. Count agreement alone is still not a general UI or focus proof;
optional entry separately verifies the exact native destination.

| Trial | Dock ready | Native entry | Final native result | Whole command |
| --- | ---: | ---: | ---: | ---: |
| Recorded create-ready, ID 29 | 133 ms | 730 ms | 888 ms, including saved typing | 2,156 ms |
| Manual CLI `desktop:create -- --enter`, ID 30 | 129 ms | 720 ms | 720 ms, no typing fixture | 1,974 ms |

Native timings begin at `runReady`'s creation start; whole-command timings
include helper build/startup and transport. Recording setup/finalization is
excluded from the whole-command column. These are individual observations,
not a latency distribution or a controlled percentage improvement across OSes.
The remaining roughly 1.25 seconds in the warm CLI run is outside the native
flow; the native slide accounts for roughly 0.58 seconds inside it.

ID 29 (`87EDA466-C83A-4168-9082-F5FFC6F6B944`) was placed after 3 and entered
through native next-Desktop action 81. Typing was saved and window 252 closed.
ID 30 (`040281B9-1053-4171-84D6-C05B9958826F`) repeated creation and entry through
the user's CLI. Both used native registration and preserved pointer position
and original application window bounds through readiness. Focus observations
lacked a known focused window, so neither is a focus-preservation pass.

The AX inventory now reports `complete=false` and `thumbnailCount=null` when
expected lists are missing. A skipped selection is explicitly marked as not
dispatched. `mission-control-inspect --disposable-session` exposes that diagnostic
without creating a Desktop. The normal create/enter flow never opens an overview.
